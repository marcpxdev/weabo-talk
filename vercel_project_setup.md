## Step 2: Environment Variables Setup

### Current Environment Variables (From Render)

**Critical Environment Variables for Migration (16 total):**

| Variable | Purpose | Required | Current Source | Migration Notes |
|----------|---------|----------|----------------|----------------|
| `SECRET_KEY_BASE` | Rails secret key for sessions, encryption | Yes | Render (auto-generated) | Vercel auto-generates |
| `APP_HOST` | Application URL (for emails) | Yes | Render (sync: false) | Update to Vercel URL |
| `APP_PROTOCOL` | Protocol for URLs | Yes | Render (https) | Keep as `https` |
| `DATABASE_URL` | Supabase database connection | Yes | Supabase Session pooler | Most critical migration |
| `SUPABASE_S3_ENDPOINT` | Supabase Storage endpoint | Yes | Supabase S3 Connection | Critical for image uploads |
| `SUPABASE_S3_REGION` | Supabase Storage region | Yes | Supabase S3 Connection | Required for S3 API |
| `SUPABASE_S3_BUCKET` | Supabase Storage bucket | Yes | Supabase S3 Connection | Must match Supabase bucket |
| `SUPABASE_S3_ACCESS_KEY_ID` | Supabase Storage access key | Yes | Supabase S3 Access Keys | Secret key for S3 access |
| `SUPABASE_S3_SECRET_ACCESS_KEY` | Supabase Storage secret key | Yes | Supabase S3 Access Keys | Secret key for S3 access |
| `REQUIRE_EMAIL_CONFIRMATION` | Email confirmation requirement | No | Render (false by default) | May need to update |
| `SMTP_ADDRESS` | SMTP server address | Yes | Render (sync: false) | Update for production |
| `SMTP_PORT` | SMTP server port | Yes | Render (587) | May change for Vercel |
| `SMTP_USERNAME` | SMTP username | Yes | Render (sync: false) | Update with production credentials |
| `SMTP_PASSWORD` | SMTP password | Yes | Render (sync: false) | Update with production credentials |
| `MAIL_FROM` | Email "from" address | Yes | Render (sync: false) | Update for production emails |
| `RAILS_LOG_LEVEL` | Rails log level | No | Render (info by default) | May increase for debugging |
| `DB_PREPARED_STATEMENTS` | Pooler vs direct connection | No | deployment.md | May need to set to `false` |

### Vercel-Specific Environment Variables

| Variable | Purpose | Required | Default |
|----------|---------|----------|---------|
| `VERCEL` | Vercel detection | No | Auto-detected |
| `VERCEL_ENV` | Environment (development/staging/production) | No | `development` |
| `VERCEL_URL` | Vercel deployment URL | No | Auto-generated |

### Step 2.2: Configure Vercel Variables

**Best Practice Configuration:**

**Secret Variables (Hidden in Vercel UI):**
```bash
# Add these as secret environment variables in Vercel dashboard:
# These will be encrypted and not visible in UI
SECRET_KEY_BASE: (auto-generated by Vercel - leave empty)
DATABASE_URL: postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
SUPABASE_S3_ENDPOINT: https://<project-ref>.storage.supabase.co/storage/v1/s3
SUPABASE_S3_REGION: ap-southeast-1
SUPABASE_S3_BUCKET: uploads
SUPABASE_S3_ACCESS_KEY_ID: <your-access-key-id>
SUPABASE_S3_SECRET_ACCESS_KEY: <your-secret-access-key>
SMTP_PASSWORD: <your-production-smtp-password>
```

**Public Variables (Visible in Vercel UI):**
```bash
# Add these as public environment variables:
APP_HOST: weabo-talk.vercel.app
APP_PROTOCOL: https
REQUIRE_EMAIL_CONFIRMATION: false
SMTP_ADDRESS: smtp.gmail.com
SMTP_PORT: 2525  # Note: Render used 587, Vercel free tier may require 2525
SMTP_USERNAME: your-email@gmail.com
MAIL_FROM: your-email@gmail.com
RAILS_LOG_LEVEL: info
DB_PREPARED_STATEMENTS: false
```

**Configuration Notes:**

1. **SECRET_KEY_BASE**: Leave empty - Vercel will auto-generate a secure secret key
2. **APP_HOST**: Update this after deployment to match your Vercel URL
3. **DATABASE_URL**: Use Supabase Session pooler connection string (not direct connection)
4. **SMTP_PORT**: May need to change to 2525 for Vercel free tier (Render used 587)
5. **DB_PREPARED_STATEMENTS**: Set to `false` if using Supabase Transaction pooler

**Alternative: Batch setup script:**
```bash
#!/bin/bash
# vercel_env_setup.sh - Setup Vercel environment variables

set -e

echo "Setting up Vercel environment variables..."

# Function to add variable if not exists
add_var() {
    local name=$1
    local value=$2
    local type="$3"  # "secret" or "public"
    
    if vercel env ls | grep -q "^$name$"; then
        echo "Variable $name already exists, skipping..."
    else
        vercel env add $name $type << EOF
$value
EOF
        echo "Added variable: $name"
    fi
}

# Add secret variables
add_var "SECRET_KEY_BASE" "" "secret"
add_var "DATABASE_URL" "postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres" "secret"
add_var "SUPABASE_S3_ENDPOINT" "https://<project-ref>.storage.supabase.co/storage/v1/s3" "secret"
add_var "SUPABASE_S3_REGION" "ap-southeast-1" "secret"
add_var "SUPABASE_S3_BUCKET" "uploads" "secret"
add_var "SUPABASE_S3_ACCESS_KEY_ID" "<your-access-key-id>" "secret"
add_var "SUPABASE_S3_SECRET_ACCESS_KEY" "<your-secret-access-key>" "secret"
add_var "SMTP_PASSWORD" "<your-smtp-password>" "secret"

# Add public variables
add_var "APP_HOST" "weabo-talk.vercel.app" "public"
add_var "APP_PROTOCOL" "https" "public"
add_var "REQUIRE_EMAIL_CONFIRMATION" "false" "public"
add_var "SMTP_ADDRESS" "smtp.gmail.com" "public"
add_var "SMTP_PORT" "2525" "public"
add_var "SMTP_USERNAME" "your-email@gmail.com" "public"
add_var "MAIL_FROM" "your-email@gmail.com" "public"
add_var "RAILS_LOG_LEVEL" "info" "public"
add_var "DB_PREPARED_STATEMENTS" "false" "public"

echo "Environment variables setup complete!"
```

## Step 3: Database Configuration

### Database Options Analysis

**Option 1: Continue with Supabase (Recommended for Phase 2)**

**Pros:**
- ✅ No migration required
- ✅ Maintains existing Supabase setup
- ✅ Familiar connection strings
- ✅ Supabase-specific features work
- ✅ Faster timeline

**Cons:**
- ❌ Need to configure Supabase connection in Vercel
- ❌ Possible performance differences

**Option 2: Vercel Postgres (Consider for Phase 3)**

**Pros:**
- ✅ Native Vercel integration
- ✅ Simpler deployment (single provider)
- ✅ Better performance in Vercel environment
- ✅ Reduces number of dependencies

**Cons:**
- ❌ Requires database migration
- ❌ Connection string format changes
- ❌ May break Supabase-specific features
- ❌ Longer timeline

**Recommendation:** Start with Supabase for Phase 2, migrate to Vercel Postgres in Phase 3 if needed.

### Database Connection Setup

**For Supabase (Recommended):**

1. **Get Supabase Connection String:**
   - Go to Supabase dashboard → Project → Connect
   - Copy Session pooler connection string (not direct connection)
   - Format: `postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`

2. **Configure in Vercel:**
   ```bash
   # In Vercel dashboard, add DATABASE_URL as secret variable
   # Value: postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
   ```

3. **Connection Pooler Configuration:**
   - Use Session pooler (not direct connection)
   - Set `DB_PREPARED_STATEMENTS` to `false` if needed

4. **Test Connection:**
   ```bash
   # Test database connectivity
   bundle exec rails db:structure:dump
   bundle exec rails db:test:prepare
   ```

**For Vercel Postgres (Future Option):**

1. **Create Vercel Postgres Instance:**
   - Go to Vercel dashboard → Settings → Integrations
   - Add Vercel Postgres database
   - Get connection string

2. **Connection String Format:**
   - Typically: `postgresql://<user>:<password>@<host>/<database>`
   - May require different format than Supabase

3. **Configuration:**
   ```bash
   # Add as secret variable in Vercel dashboard
   DATABASE_URL: postgresql://vercel_user:vercel_password@ep-<project-id>.pooler.supabase.com:5432/postgres
   ```
